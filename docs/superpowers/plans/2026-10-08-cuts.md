# Cuts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace in-memory frame and chip cutting with table-based cuts in `geodata/cuts`, and move prediction to save-then-merge.

**Architecture:** `cuts.stacks/frames/chips` are table-in, table-out and read the item table through PySTAC classes; `cuts.select*` applies one window to an opened sample; `cuts.layout` is the one chip layout both cutting and merging use.

**Tech Stack:** geopandas, pystac (Projection, Datacube), tiler, xarray, Lightning.

**Spec:** `docs/superpowers/specs/2026-10-08-cuts-design.md`

## Global Constraints

- No commits; the tree holds unrelated uncommitted work.
- Cuts open no file; facts come from `table.to_items` and PySTAC classes.
- `geodata` imports no torch; `model` does not import `ml`.
- Google-style docstrings; `uv run pytest`, `uv run ruff check`.
- The code for Tasks 1-2 was run as prototypes and compared against the existing cutters on Zarr and COG samples (see the spec). Tasks 3-6 were not prototyped.

## Review Focus

1. A timeless raster given a caller's `datetime` must still be timeless to `frames` (it states no Datacube labels).
2. Groups of one sample on different grids must raise, naming the groups.
3. Preprocessing that renames rasters: model context must see the prepared rasters' time labels, not the saved groups'.
4. A window table whose rows lack `geosave:stack` must raise a clear error.
5. Chips of one raster predicted on different processes must still merge.
